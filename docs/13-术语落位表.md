## 使用规则（写新章术语清单前必查）

1. **查 id**：先在本表搜目标 id——存在则标「复用」，注明定义批次；不存在才可「新增」。
2. **查别名撞车**：新增词的 aliases 不得与已有词条的 term/aliases 重复（如 toctou/toctou-race 的别名严格切分先例）。
3. **落库后更新本表**：工程师把新词落进 glossary.ts 后，把「待落库」改为「已落库」，并把条目移到对应主题批次。
4. **锚点三档标注**（与各主题文档一致）：本条新增（不加标注）/ 本章前条 / 复用，更早章节。

## 维护规则（随章节增量）

1. 每章写完术语清单 → 先查本表 → 标复用/新增 → 本表补一行（或移到批次表）。
2. 工程师落库 glossary.ts 后 → 「待落库」改「已落库」。
3. 别名撞车争议（如 toctou/toctou-race）按「机制词/漏洞词分开、别名各归其主、related 单向」处理，先例见批次 7。
4. 复用存疑时（如 arbitrary-rw 是否含文件场景）：查 glossary.ts 原文 plain，确认后在本表备注栏写明依据——本表就是干这个的。
