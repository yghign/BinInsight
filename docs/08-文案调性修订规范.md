## 3.2 五条调性规则

**规则 1 · 正文调性：专业、简洁、书面。**
直接使用准确的专业术语（SQL 注入、缓冲区溢出、越权、参数化查询、模板注入等），句子完整、书面化、信息密度优先。**禁用口语与堆砌类比**（禁用词表见 §3.5）。参照标准 = 用户工具书（`网络安全漏洞类型工具书.md`）：如「一句话：把用户输入拼进 SQL 语句，导致攻击者可以改写 SQL 语义，读取、篡改数据甚至执行系统命令」——专业、准确、无类比。

**规则 2 · 类比的使用规则（点到即止）：**
只在「一句话」字段或极难的抽象概念（信任边界、盲注、漏洞链这类）处，最多保留 **1 个精炼类比**，≤30 字，点到即止，不展开叙述。正文其余部分（成因/分类/特征/危害/验证/防护/易错点）**一律不用生活化类比**。已写进类比库（docs/06 §2.8）的类比只允许出现在上述受限位置。

**规则 3 · 白话解释的去处（下沉，不在正文堆白话）：**
详细的白话解释下沉到两处：① 术语浮层（TermButton 点开的 `glossary.ts` plain 字段）；② 「易错点」段落（点破误区时允许轻量白话）。正文段落不再出现「说白了/你可以理解成/也就是说」式白话铺陈。

**规则 4 · 术语使用的专业规范：**
与业界标准一致：XSS 就写「跨站脚本（XSS）」，不写「跨站脚本攻击那种东西」；SQL 注入不写「数据库那种注入」。术语首次出现可带英文原名（如「服务端模板注入（SSTI）」），其后用中文简称。同一篇内用词统一（如统一「注入」不混用「插注」）。

**规则 5 · 修订示例对照：** 见 §3.6，工程师照此标准改全部条目。

## 3.6 修订示例对照（工程师照此改全部条目）

### 示例 1 · `ch1.ts` SQL 注入 `oneLiner`（反例 → 专业版）

**改写前（口语化过度）**：
> 把用户输入拼进 SQL 语句，等于把笔交给了陌生人——原本该是「数据」的输入被当成了「命令」，攻击者能改写整句问话，读走、改掉甚至删掉数据。

**改写后（专业）**：
> 把用户输入拼接进 SQL 语句，导致输入被当作 SQL 代码解析，攻击者可改写语句语义，造成未授权的数据读取、篡改或删除。

**改动点**：① 删「把笔交给了陌生人」（生活类比，且不精确——注入的本质是「数据进入指令位」而非「交给别人」）；② 「整句问话」→「语句语义」；③ 「读走、改掉甚至删掉数据」→「未授权的数据读取、篡改或删除」（业界危害表述）；④ 保留一处最准确的技术判断「输入被当作 SQL 代码解析」。

### 示例 2 · `ch1.ts` SQL 注入 `cause`（反例 → 专业版）

**改写前（口语化过度）**：
> 程序要查数据库，得先写一句 SQL。偷懒的写法是把用户输入直接用 + 拼进去：
> …
> 如果用户乖乖输入 alice，语句是查 alice；如果输入 alice' OR '1'='1，拼出来的句子就变成了「查 alice，或者 1 等于 1」——1 永远等于 1，于是整张用户表都被查出来了。和主线的对应：这行 + 拼接就是 Web 版的 strcpy——它不检查「输入里有没有不该出现的字符」，就像 strcpy 不检查长度。

**改写后（专业）**：
> 程序通过字符串拼接构造 SQL 语句时，用户输入直接进入语句结构：
> …（代码块不变）
> 若输入为 alice，语句按预期查询该用户；若输入 alice' OR '1'='1，引号闭合了字符串字面量，后续 OR 条件恒为真，查询返回全部行。该写法与主线 strcpy 的缺陷同源：均未对输入做边界或语义校验，数据进入了指令位。

**改动点**：① 「得先写一句 SQL。偷懒的写法」→「通过字符串拼接构造 SQL 语句时」（删「偷懒」的评价式口语）；② 「用户乖乖输入」→「若输入为」；③ 「拼出来的句子就变成了『查 alice，或者 1 等于 1』——1 永远等于 1，于是整张用户表都被查出来了」→「引号闭合了字符串字面量，后续 OR 条件恒为真，查询返回全部行」；④ 主线对应保留（教学需要）但改书面：「和主线的对应：…就像 strcpy 不检查长度」→「该写法与主线 strcpy 的缺陷同源：均未对输入做边界或语义校验，数据进入了指令位」。

### 示例 3 · `ch1.ts` 分类表「二次注入」（轻量示例）

**改写前**：`坏数据先存起来，取出时才炸`
**改写后**：`恶意数据先入库（转义后），取出再拼接时才触发`
**改动点**：「坏数据」「才炸」是口语/比喻，改技术表述；保留「入库-取出-触发」的时序要点。

> 以上 3 例覆盖「一句话 / 成因 / 分类」三类字段。其余字段照 §3.4 调性矩阵与 §3.5 禁用表同标准批量修订；每条改完自测一遍：**一句话能否直接放进工具书而不违和**（这是「专业性」的操作性判据）。
