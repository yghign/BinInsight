> **「真实输出 / 演示样例 / 规划中」** 三态标签之一；任何统计数字都来自报告对象，不硬编码。

## 一、演示前 1 分钟复现（断网可完成）

### 1. 网页侧（不需要联网、不需要装环境）

```
npm install                 # 只装现有依赖，不新增
npx tsc --noEmit            # 类型检查
npm run check:honesty       # 全站诚实文案自检
npm run build               # 生成 8 个静态主线页 /learn/l0 .. /learn/l7
npm start                   # 本地起服务；也可用纯静态产物，无外部服务、无 API Key
```

打开 `/tools/dilipa`，自上而下点三个按钮即可完成闭环，全程零网络请求：

| 动作 | 页面标签 | 说明 |
|---|---|---|
| 「查看预置样例」 | 演示样例 | 渲染 `src/data/sample-report.json`，统计全部来自该报告对象 |
| 「下载样例 JSON」 | 演示样例 | `Blob + <a download>` 存到本地，不走网络 |
| 「导入我自己的 JSON」 | 真实输出 | `FileReader.readAsText` 本地读取，不上传、不写 localStorage |

### 2. Python 侧（真实解析出一份演示样例报告）

在 `C:\Users\Lenovo\WorkBuddy\2026-11-13-10-08-35\deliverables\` 下执行，解释器用演示 venv：

## 三、8 道理解标志题（L0~L7，每级 1 道）

来源：`docs/01-增量PRD.md` 4.2 递进链，与 `src/data/lesson.ts` 每级 `understanding` 字段一致。
判定标准：**不看提示、独立说出要点即算通过**；S2 要求 ≥6 道。

| # | 级 | 问题 | 通过标准（标准答案要点） |
|---|---|---|---|
| 1 | L0 起点 | 程序读到你的输入之后，会把输入放到哪里？ | 能说出「程序会读输入，并把输入放进一个固定大小的盒子」（菜谱 + 冰箱的比喻） |
| 2 | L1 装不下 | 输入比盒子长的时候，多出来的数据会怎么样？ | 能指出「多出来的数据盖住了别的东西」，并答出「盖住的是程序下一步要跳去的地方」（返回地址） |
| 3 | L2 找到它 | 怎么在一堆汇编里找到那个不检查长度的调用？ | 能在汇编里点中 `call strcpy` 那行，并说出「它不检查长度」；两步法：先找 call，再看名字 |
| 4 | L3 修好它 | 把 `strcpy` 换成 `strncpy`，最关键的变化是什么？ | 能说出「加了长度上限，最多只拷这么多」；「手动补 `\0`」算注意事项，不算新概念 |
| 5 | L4 能碰到吗 | 输入 `"hi"` 为什么走不到 `strcpy` 那一行？ | 能说出「两道关都过了才会走到 strcpy」，并解释 A 场景因为「输入够长吗」没过而提前结束 |
| 6 | L5 崩给你看 | 现场里 `rip` 变成 `0x41414141`，说明什么？ | 能说出「一串 'A' 写到了本该放下一步地址的地方」；**不需要会敲任何 GDB 命令** |
| 7 | L6 加把锁 | Canary 这把「锁」到底做了什么？ | 能说出「Canary 是返回地址前的一个随机数，被改动就立刻终止程序」；NX / ASLR 一句话带过 |
| 8 | L7 自己走一遍 | 沙箱里哪一步用到了 L2 的 `call`？哪一步用到了 L6 的 Canary？ | 不看提示独立完成；能对着标准答案说出「定位漏洞点用了 L2 的 call、开防护用了 L6 的 Canary」 |

> 每级页面末尾还有一张 2 选 1 自检卡（`SelfCheckCard`）：答错立即给白话解释、可重来、不扣分，
> 答对才 `markDone()` 解锁下一级。8 道题与自检卡互为印证。

## 五、三条校验命令与已知遗留

```bat
npx tsc --noEmit
npm run check:honesty
npm run build
```

三条命令的结论都来自对磁盘文件的真实检查，不是预写结论；`check:honesty` 排除
`src/data/source-state.ts`（三态词表位）与脚本自身（禁用词字面量本身在这两处）。

已知遗留（演示时如实说明，不掩饰）：

1. 仓库 `dilipa-tool/dilipa/disassembler.py` 的 `_parse_call_target()` 只认 `@plt`，
   纯数字 call 目标会漏检 —— 本次按要求**不改仓库 .py**，改由课前独立脚本补齐映射。
2. 网页所谓「diff」是 `src/lib/str-diff.ts` 的按行字符串对齐，**不是**语法树（AST）对比。
3. 二进制重写、补丁等价性校验、反编译提升、Mutagen 全部属于「规划中」，本次未实现。
4. L8 拓展区（旧 step1~4、`/reference/*`、`/tools/*`、`/terms`、本地深度案例）内容保留但
   **不计入主线、不演示、不考核**，页顶统一挂「拓展阅读（不考）」横幅。
